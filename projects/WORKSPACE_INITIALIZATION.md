# 项目工作区初始化

## 核心作用

指导 Agent 创建或恢复 `workspaces/` 实例，接入由独立 Git 管理的实际项目仓库，并完成投入日常协作前的必要初始化与检查。

## 创建工作区实例

1. 确认工作区实例名称、工作区远端地址、实际项目仓库情况及远端地址，以及初始化项目文档所需的已知信息。
2. 从 `template/` 创建对应的 `workspaces/` 实例；同名实例目录已存在时，先向用户说明并确认处理方式，不自动覆盖。
3. 将实例初始化为独立的工作区 Git，并关联其私有远端。
4. 清理实例 `repository/` 中的模板占位后，建立由项目仓库 Git 独立管理的实际项目：已有项目仓库时，将其接入 `repository/`；尚无项目仓库时，在 `repository/` 中初始化新的项目仓库，并关联其远端。
5. 初始化项目协作上下文：
   - 已有项目时，结合实际项目内容和用户补充信息，提炼并确认 `PROJECT.md` 与 `CURRENT.md`。
   - 新项目时，以两个文件的职责和章节为目标，Agent 根据具体项目和用户已有描述，按需追问影响项目定义或当前状态的关键信息，协助澄清和提炼；用户确认后落盘，不自行补全无法确定的内容。
6. 检查两个 Git 仓库的管理边界，并为工作区 Git 建立初始版本。

## 恢复工作区实例

1. 确认工作区 Git 和实际项目仓库 Git 的远端地址；同名实例目录已存在时，先向用户说明并确认处理方式。
2. 将工作区 Git 恢复到 `workspaces/` 对应实例，再将实际项目仓库恢复到实例的 `repository/`。
3. 检查两个仓库是否与远端最新提交一致，并读取 `PROJECT.md`、`CURRENT.md` 等关键上下文，确认现有信息可以支持继续协作；发现缺失或过时时向用户说明。

## 完成条件

- **项目上下文已就绪**：创建时，`PROJECT.md` 和 `CURRENT.md` 的必要章节已经初始化，能够准确表达当前已确认的信息并支持首次规划，且已经用户确认；恢复时，已有内容已经正确恢复。模板和实例规则中的按需内容不要求全部填写。
- **实例 Git 边界正确**：工作区 Git 不跟踪 `repository/`，项目仓库 Git 能够独立正常工作，两个仓库均已正确配置对应远端。
- **协作路由可用**：实例内的 `AGENTS.md` 和适用规则能够正常读取，Agent 可以结合项目定义和当前状态进入后续规划、执行与复盘流程。
