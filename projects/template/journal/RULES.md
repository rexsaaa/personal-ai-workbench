# 项目复盘规则

## 核心作用

定义 Agent 在当前项目中协助用户记录执行情况、开展复盘和维护记录时共同遵守的规则。

## 复盘原则

- 创建日、周、月复盘时，分别使用对应周期目录中的 `TEMPLATE.md` 实例化文件；同时涉及多个周期时，按照日、周、月的顺序逐层汇总。
- 复盘以对应计划、下级 Journal 和对话中能够确认的事实为依据；无法确认的信息标记为不精确或未确认，不自行臆测。
- 复盘重点对照目标、完成标准和实际结果，区分完成、部分完成与未执行；可选任务未执行不自动视为失败。
- 周复盘和月复盘只提炼下级 Journal 的关键结果与规律，不重复复制每日时间线和具体细节。
- 默认由 Agent 根据现有记录生成简练但完整的复盘，不要求用户独立撰写；复盘用于评价计划与执行效果、改善后续协作，不对用户本人做价值判断。
- 每次复盘形成明确的调整结论，供 Task 生成后续计划；Journal 不直接创建或修改计划。

## 通用规则

### 收口复盘 SOP

当用户明确表示结束今日工作、要求收口或明确要求复盘时触发。

- **确定复盘范围**：根据当日日计划中的“收口安排”和用户明确提出的要求，确定本次需要生成的日、周、月 Journal；不在 Journal 内重新计算周期。
- **读取必要依据**：读取各项复盘对应的计划、已有下级 Journal，以及当前对话中能够确认的执行情况。
- **逐层生成复盘**：本次涉及多个周期时，按照日、周、月的顺序，使用对应 `TEMPLATE.md` 生成适用的 Journal。
- **处理信息缺口**：只使用能够确认的信息完成复盘；无法确认的内容明确标记，不自行补全，也不阻断收口。关键信息缺失时，在交付结果中集中说明。
- **衔接后续计划**：全部适用复盘完成后，根据当日日计划中“需要生成的计划”，进入 Task 的“计划生成 SOP”。

#### 普通工作日

1. 读取当日日计划和本次 session 中能够确认的执行时间线。
2. 使用 `daily/TEMPLATE.md` 生成当日日复盘。
3. 记录实际投入、任务完成情况、主要结果、偏差原因和调整结论。

#### 周收口日

1. 先按“普通工作日”中的步骤完成当日日复盘。
2. 读取本周计划及本周全部日 Journal。
3. 使用 `weekly/TEMPLATE.md` 生成本周复盘。
4. 记录本周目标与任务完成情况、主要成果、偏差原因和调整结论。

#### 月收口日

1. 先按“周收口日”中的步骤完成当日日复盘和最后一个周周期的周复盘。
2. 读取本月计划及纳入本月复盘的全部周 Journal。
3. 使用 `monthly/TEMPLATE.md` 生成本月复盘。
4. 记录本月目标、月度成果和各周目标的完成情况，以及主要偏差、原因和调整结论。
