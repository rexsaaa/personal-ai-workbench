# 框架演进规则

## 核心作用

明确本框架 `personal-ai-workbench` 当前所处阶段及其有效的演进规则，指导 Agent 围绕当前阶段目标设计、验证和调整框架；进入下一阶段时，经用户确认后更新阶段和适用规则。

## 当前阶段

- **阶段**：第一版搭建阶段。
- **目标**：形成可初始化、可实例化，并能完成基本协作与记忆沉淀闭环的第一版 `personal-ai-workbench`。
- **完成条件**：
  - 根层、通用规则、用户画像和项目工作区的职责与路由清晰，不存在明显冲突。
  - 新用户能够初始化个人画像，并从模板创建具体项目工作区。
  - Agent 能够读取适用上下文，协助推进和复盘项目，并经用户确认沉淀需要跨会话保留的信息。
  - 完成一次真实实例化和最小闭环验证，由用户确认进入复用优化阶段。

## 当前演进规则

当前阶段采用从根到叶、逐层稳定的迭代方式。每一层完成审核和验证后，作为下层设计的依据；除非发现上层边界错误或获得真实使用反馈，不重新展开已经稳定的层级。

1. **以已确认目标为起点**：以项目定位、上级职责和已经确认的结论作为当前设计依据；未经审核的现有内容只作为参考素材。
2. **确定当前层的广度边界**：先明确当前层负责的问题域、直接子项及其职责，不提前设计更深层实现。
3. **稳定当前层作为下层约束**：当前层通过审核后作为下层设计依据；其问题域、职责边界或接口变化时，复审上级接口和受影响子树，不波及无关同级项。
4. **逐项深入直接子层**：每次只选择一个直接子项，按照“职责、最小结构、具体内容”的顺序完善；当前子项稳定后再处理下一个。
5. **控制第一版建设范围**：只实现当前阶段已经出现且现有结构无法承载的必要需求，不追求一次性完备，也不为假设需求提前扩展。
6. **验证后继续向下**：每完成一项，回读并模拟真实流程；确认其与上级目标一致、职责清楚、路由无断点且最小场景可运行后，才暂时稳定并进入下一项。整个框架完成后，再进行一次真实实例化验证。

## 阶段更新

只有用户明确确认当前阶段完成并进入下一阶段后，才更新“当前阶段”和“当前演进规则”。更新时保留仍然适用的规则，调整发生变化的规则，删除已经失效的规则；旧阶段和旧规则由 Git 历史保留，不在本文档中归档。
