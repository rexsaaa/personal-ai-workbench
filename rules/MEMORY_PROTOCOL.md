# 长期协作记忆协议

## 核心作用

指导 Agent 在协作中识别需要跨会话保留并对后续协作具有价值的信息，判断其一级归属并主动提出记录或维护建议；经用户确认后，按对应模块的路由完成记录和整理。

## 持续识别

协作过程中留意需要跨会话保留，并会影响后续项目推进、跨项目协作或框架演进的信息；默认在实质性任务完成或复盘时集中检查，避免频繁打断当前任务。

重点关注：

- **连续性信息**：需要跨会话延续当前协作状态的信息，如项目目标、当前阶段、关键决策、进展结果、下一步，以及会影响后续协作的用户背景、方向、资源、约束或偏好变化。
- **积累性信息**：值得以后复用或持续优化的信息，如解决方案、工作流程、复盘经验、协作方法、个人洞察或框架改进。
- **维护信号**：已有协作记忆已经过时、重复、冲突或归属错误。

只有候选内容明确、尚未被现有记录准确反映，并且会影响后续协作或具有明确复用价值时，才主动提出记录或维护建议。不会影响后续协作的临时细节、缺乏依据的推测和无需更新的重复内容，不主动处理。

## 信息分类

按候选信息的适用范围判断一级归属：

- 仅对某个具体项目有效的目标、状态、决策、结果、项目经验和问题解决过程，进入 `projects/`。
- 对当前用户跨项目有效的背景、方向、能力、资源、约束、协作偏好、经验和个人洞察，进入 `profile/`。
- 对整个工作台或不同用户实例普遍适用的规则和机制改进，进入 `rules/`。

同一事项产生不同适用范围的信息时，分别提炼后归入对应模块，不原样重复存放。

本协议只判断一级归属，不定义模块内部的具体落点。

## 确认与落盘

1. 向用户说明建议记录或维护的关键内容、一级归属、处理方式和判断理由。
2. 用户确认建议后，进入相关模块，并按其 `AGENTS.md` 读取相关规则，确定具体文件、内容形式或维护方式。
3. 新增或更新记录时，结合当前讨论、任务结果和目标模块规则，将候选信息提炼为当前有效的事实、状态或结论，并保留必要的背景和适用条件；不直接复制原始讨论，也不将临时情况过度概括为长期记忆。
4. 按 `CHANGE_PROTOCOL.md` 完成修改、检查和交付。

## 现有记忆维护

对于“持续识别”发现的维护信号，提出更新、合并、删除或迁移建议，并按“确认与落盘”流程处理，使现有记录保持准确、有效且归属正确。

每次记录或维护协作记忆时，只检查目标文件及与本次信息直接相关的现有记录，判断是否出现过时、重复、冲突或归属错误。

在阶段性复盘、同一模块连续出现维护信号，或用户明确要求时，对对应模块进行阶段性整理。
