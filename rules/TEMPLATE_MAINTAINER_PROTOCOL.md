# 模板维护与贡献协议

## 作用与仓库模型

本协议用于从私人实践中维护公开模板，并向原始公开模板仓库贡献通用改进。

```text
私人实例 main ──日常同步──▶ 私有 origin/main
        ⇅ 选择性采用 / 提炼公开改进
当前公开工作模板 upstream/main
        ├── 共同维护者：原始公开模板仓库 main
        └── fork 用户：个人公开 fork main
                            ⇅ 选择性更新 / 跨仓库 PR
                      原始公开模板仓库 main
```

原始公开模板仓库是本项目正式发布公开模板的仓库，其 `main` 是所有贡献 PR 的最终目标。具有该仓库写权限的共同维护者直接以它作为公开工作模板；其他用户通过个人公开 fork 参与维护。

| 角色 | `origin` | `upstream` | 原始模板引用 |
| --- | --- | --- | --- |
| 共同维护者 | 私人实例仓库 | 原始公开模板仓库 | 与 `upstream` 相同 |
| fork 用户 | 私人实例仓库 | 个人公开 fork | 原始公开模板仓库，只读 |

私人实例 `main` 初始来自 `upstream/main`，实例化后独立演进。fork 用户日常维护 `origin` 和 `upstream`，只在选择原始模板更新或准备跨仓库 PR 时获取原始模板引用。

fork 用户以个人公开 fork 作为中间层：既可以选择性接收原始公开模板的更新，也可以把私人实践中的通用改进先发布到个人 fork，再通过跨仓库 PR 反向贡献给原始公开模板。

## 核心原则

- **私有与公开分离**：完整私人实例只进入 `origin`；`upstream` 只保存模板内容和经过提炼、脱敏的公开改进。
- **公开工作模板**：fork 用户以 `upstream/main` 维护自己的公开模板版本，作为私人实践与原始公开模板之间的中间层。
- **选择性演进**：原始模板、个人 fork 和私人实例之间都由用户选择需要采用的更新。
- **隔离发布**：每次发布都使用独立 `template/*` 候选分支。
- **统一审核**：同仓库 PR 和跨仓库 PR 遵循相同审核流程。
- **两个人工关口**：贡献者确认候选内容，目标仓库维护者确认是否合并。同一个人承担两种角色时仍分别确认。

## 两条发布路线

所有用户都先从私人实践中提炼通用改进，通过候选分支和同仓库 PR 更新当前使用的公开 `upstream/main`。

共同维护者的 `upstream` 就是原始公开模板仓库，因此完成这次发布后，改进已经进入原始公开模板。fork 用户的 `upstream` 是个人公开 fork；需要继续向原始公开模板贡献时，再发起一次跨仓库 PR。

| 发布路线 | 适用用户 | 候选内容来源 | 候选分支基线 | 推送位置 | PR 目标 |
| --- | --- | --- | --- | --- | --- |
| 更新当前公开工作模板 | 共同维护者、fork 用户 | 私人 `main` 中的通用实践 | `upstream/main` | `upstream/template/*` | 同仓库 `upstream/main` |
| 向原始公开模板贡献 | fork 用户 | 个人公开模板 `upstream/main` | 原始公开模板仓库 `main` | `upstream/template/*` | 跨仓库原始公开模板仓库 `main` |

## 通用七阶段流程

七阶段适用于上述两条发布路线。

| 阶段 | Agent 自动完成 | 人工关口 |
| --- | --- | --- |
| 1. 准备 | 检查工作区和远端，保存现有修改，获取最新内容来源与候选基线 | 无 |
| 2. 提炼候选 | 创建隔离 worktree 和 `template/*` 分支，提炼、脱敏、修改并验证 | 无 |
| 3. 候选审核 | 输出最终文件、完整 PR 差异、隐私结果和结构影响 | **贡献者确认候选内容** |
| 4. 创建 PR | commit、push，并按发布路线创建同仓库或跨仓库 PR | 无 |
| 5. PR 自动审核 | 检查 base/head、最终差异、适用范围、重复或重叠、冲突、checks、测试、head SHA 和 ruleset | 无 |
| 6. 合并审核 | 输出简洁的合并前报告和建议合并方式 | **目标仓库维护者确认是否合并** |
| 7. 发布收口 | 锁定已审核的 head SHA、按 ruleset 合并、清理候选分支并核对目标仓库 `main` | 无 |

第 3 阶段确认前不提交、推送或创建 PR；第 6 阶段确认前不合并。默认使用 GitHub CLI 完成 PR 操作，Agent 使用 `gh pr create`、`gh pr view`、`gh pr diff`、`gh pr checks` 和 `gh pr merge` 完成相应操作。

## 公开边界

每次发布只提炼适合进入目标公开模板的内容：

- 从私人 `main` 更新当前公开 `upstream/main` 时，排除个人信息、凭据、实例记录和其他私人内容。
- 从个人 `upstream/main` 向原始公开模板仓库贡献时，进一步排除仅适合个人 fork 的设计和无关差异。
- 候选应保持结构完整、能够独立使用，并与目标模板的职责和约束一致。

Agent 根据当前仓库状态自行选择路径识别、差异比较、隔离环境、脱敏和验证方法。无法确定公开边界的内容进入第 3 阶段候选报告，由贡献者决定。
