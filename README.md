# Personal AI Workbench

`personal-ai-workbench` 是一套以个人为中心、跨设备复用，并与具体领域和单一 AI 解耦的 AI 原生长期项目与工作协作框架。

它通过 Git 同步的显式文档保存用户偏好、项目上下文和实践经验，使不同设备、不同 Agent 或新的 session 能够恢复协作状态，而不依赖模型自身的长期记忆。

在此基础上，Agent 可以继续协助用户规划、执行和复盘任务，并沉淀值得长期保留的信息。

## 解决的问题

- 更换设备、Agent 或 session 后，需要反复说明个人偏好和项目背景。
- AI 协作容易停留在单次对话，难以持续积累对用户的理解并改进协作方式。
- 项目推进缺少结合用户背景、目标和约束的规划、执行与复盘闭环。
- 对话中形成的项目经验、解决方案和个人洞察，难以转化为以后可复用的长期积累。

## 核心能力

- **持续上下文**：保存跨项目生效的用户画像和具体项目状态，使 Agent 能够快速接手任务。
- **个性化协作**：持续记录经用户确认的协作偏好和有效方式，使后续协作逐步贴合用户。
- **项目推进闭环**：结合用户和项目上下文，协助澄清目标、制定计划、推进执行并复盘结果。
- **经验沉淀与演进**：主动识别值得长期保留的项目经验、个人洞察和框架改进，经用户确认后沉淀到对应模块。

持续使用后，用户可以减少重复交代背景的成本，更清楚地认识自己的方向、能力和协作偏好，并逐步形成适合自己的长期工作方式。

## 快速开始

1. 克隆本仓库，并基于它建立自己的私有工作台仓库。后续可以根据实际使用情况持续调整框架，形成个人定制的工作台。
2. 在工作台根目录开始协作，让 Agent 从根 `AGENTS.md` 读取适用规则。
3. 了解三个核心目录：
   - `rules/`：保存整个工作台通用的协作与管理规则。
   - `profile/`：保存跨项目生效的用户画像、协作偏好和个人洞察。
   - `projects/`：提供项目工作区模板，并承载各具体项目的管理实例。
4. 工作台提供可持续更新的用户画像与协作规则机制，使 Agent 能够跨会话了解用户并逐步优化协作方式；需要使用时，让 Agent 按 `profile/` 的流程引导完成初始化。
5. 工作台提供结合项目上下文的规划、执行与复盘机制，用于持续推进具体项目；需要使用时，让 Agent 按 `projects/` 的流程创建或恢复工作区实例并完成项目初始化。
6. 工作区就绪后，让 Agent 根据项目上下文完成首次规划，进入日常执行、复盘与收口。

## 日常工作方式

1. 进入对应工作区实例后，Agent 结合用户画像、通用规则、项目定义、当前状态和有效计划恢复协作上下文。
2. 用户说明当前时间和可用时长，Agent 根据当日计划安排本次工作；发生中断或续接时，根据剩余时间继续调整。
3. 用户结束当日工作时，Agent 根据收口安排完成适用的日、周或月复盘。
4. Agent 根据复盘结果维护项目上下文、生成后续计划，并完成工作区 Git 的每日收口。
5. 协作中产生需要跨会话保留的信息时，Agent 主动提出沉淀建议，经用户确认后记录到对应模块。

## 适用对象

适合希望长期使用 AI 辅助学习、开发、工作或个人成长，并愿意在持续协作中沉淀个人信息、项目上下文和实践经验的人。

尤其适合需要跨设备或 Agent 接续任务、管理长期项目，或希望逐步形成个人协作体系的用户。框架不绑定具体领域或特定 Agent。

## Git 管理边界

- **工作台 Git**：管理工作台框架、通用规则、用户画像和项目工作区模板，建议同步到用户自己的私有远端仓库。
- **工作区 Git**：每个项目工作区实例独立管理项目背景、状态、计划和复盘，不进入工作台 Git，并使用自己的远端同步。
- **项目仓库 Git**：实际项目内容由项目仓库独立管理，不进入工作区 Git。
