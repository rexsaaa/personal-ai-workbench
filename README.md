# Personal AI Workbench

`personal-ai-workbench` 是一套以个人为中心、跨设备复用，并与具体领域和单一 AI 解耦的 AI 原生长期项目与工作协作框架。

它通过 Git 同步的显式文档保存用户偏好、项目上下文和实践经验，使不同设备、不同 Agent 或新的 session 能够恢复协作状态，而不依赖模型自身的长期记忆。

在此基础上，Agent 可以继续协助用户规划、执行和复盘任务，并沉淀值得长期保留的信息。

## 解决的问题

- 更换设备、Agent 或 session 后，需要反复说明个人偏好和项目背景。
- AI 协作容易停留在单次对话，难以持续积累对用户的理解并改进协作方式。
- 项目推进缺少结合用户背景、目标和约束的规划、执行与复盘闭环。
- 对话中形成的项目经验、解决方案和个人洞察，难以转化为以后可复用的长期积累。

## 核心能力

- **持续上下文**：保存跨项目生效的用户画像和具体项目状态，使 Agent 能够快速接手任务。
- **个性化协作**：持续记录经用户确认的协作偏好和有效方式，使后续协作逐步贴合用户。
- **项目推进闭环**：结合用户和项目上下文，协助澄清目标、制定计划、推进执行并复盘结果。
- **经验沉淀与演进**：主动识别值得长期保留的项目经验、个人洞察和框架改进，经用户确认后沉淀到对应模块。

持续使用后，用户可以减少重复交代背景的成本，更清楚地认识自己的方向、能力和协作偏好，并逐步形成适合自己的长期工作方式。

## 快速开始

克隆本仓库后，使用能够访问并修改本地文件、执行 Git 操作的 Agent，在工作台根目录提出首次请求：

> 我刚从模板创建这个工作台。请读取根目录的 `AGENTS.md` 和 `README.md`，检查当前仓库关系和初始化状态，分阶段引导我建立私人实例、初始化个人上下文并接入第一个项目。涉及远端写入、覆盖或公开内容前，请先向我确认。

用户不需要预先理解全部文件或指定实现步骤。根 `AGENTS.md` 会将 Agent 路由到当前任务需要的规则、个人上下文和项目管理流程；Agent 应根据实际状态选择合适的处理方式。

### 1. 建立私人工作台

按[“私人仓库与模板更新”](#私人仓库与模板更新)建立自己的私人工作台。完成后，本地 `main` 应用于日常使用并同步到私人远端，公开模板只作为可选的更新来源。

### 2. 初始化个人上下文

如果用户画像或协作规则仍待初始化，Agent 会根据当前情况逐步引导用户确认需要长期保留的背景和协作方式。用户可以跳过不清楚、不愿记录或暂时不需要的内容，也可以中断后继续；只有用户确认的信息才会写入工作台。

### 3. 接入第一个项目

需要开始管理具体项目时，向 Agent 说明项目情况和目标。例如：

> 我想用这个工作台管理一个项目，请帮我创建或恢复对应工作区，并接入实际项目仓库。

Agent 会根据现有项目和仓库状态选择合适的处理方式，建立独立的工作区管理实例，确认其与实际项目仓库的 Git 边界，并初始化足以支持后续协作的项目上下文。

### 4. 开始日常使用

工作区就绪后，在对应工作区中继续与 Agent 协作。Agent 会结合个人上下文、项目定义和当前状态协助规划、执行与复盘，并在需要沉淀长期信息时先征求用户确认。

首次使用完成时，应达到以下状态：

- 私人工作台能够安全同步，日常内容不会误推送到公开模板。
- 个人上下文已经完成必要初始化，或由用户明确选择暂缓。
- 至少一个项目工作区已经就绪，并与实际项目仓库保持清晰的管理边界。
- Agent 能够从现有文档恢复上下文并开始推进任务。

## 私人仓库与模板更新

工作台会保存个人画像、协作偏好和项目管理信息，建议将个人实例同步到自己的私有仓库，同时保留公开模板作为可选的更新来源。具体项目工作区和项目仓库仍按“Git 管理边界”独立管理。

```text
公开模板 upstream/main ──提供可选更新──▶ 本地私人工作台 main
                                                │
                                                └──日常同步──▶ 私有仓库 origin/main
```

- `origin` 指向用户自己的私有仓库，本地 `main` 默认与其同步。
- `upstream` 指向公开模板，仅用于查看和获取后续模板改进。
- 私人实例归用户所有，可以自由调整，也可以完整采用、部分采用或忽略模板更新。

首次配置时，先准备一个私人远端仓库，再自行或让 Agent 根据当前仓库、分支和远端状态建立上述关系。完成后应确认：

- `origin` 和 `upstream` 指向正确的仓库。
- 本地 `main` 跟踪私人 `origin/main`，日常推送不会进入公开模板。
- 现有分支、远端配置和提交历史未被意外覆盖。

日常修改只需同步到 `origin`。需要模板更新时，先获取并查看 `upstream/main` 的变化，再由用户决定完整采用、部分采用或忽略；采用后的结果仍进入私人 `main` 并同步到 `origin`。个人信息和实例专用内容不得推送到公开模板。

## 日常工作方式

1. 进入对应工作区实例后，Agent 结合用户画像、通用规则、项目定义、当前状态和有效计划恢复协作上下文。
2. 用户说明当前时间和可用时长，Agent 根据当日计划安排本次工作；发生中断或续接时，根据剩余时间继续调整。
3. 用户结束当日工作时，Agent 根据收口安排完成适用的日、周或月复盘。
4. Agent 根据复盘结果维护项目上下文、生成后续计划，并完成工作区 Git 的每日收口。
5. 协作中产生需要跨会话保留的信息时，Agent 主动提出沉淀建议，经用户确认后记录到对应模块。

## 适用对象

适合希望长期使用 AI 辅助学习、开发、工作或个人成长，并愿意在持续协作中沉淀个人信息、项目上下文和实践经验的人。

尤其适合需要跨设备或 Agent 接续任务、管理长期项目，或希望逐步形成个人协作体系的用户。框架不绑定具体领域或特定 Agent。

## Git 管理边界

- **工作台 Git**：管理工作台框架、通用规则、用户画像和项目工作区模板，建议同步到用户自己的私有远端仓库。
- **工作区 Git**：每个项目工作区实例独立管理项目背景、状态、计划和复盘，不进入工作台 Git，并使用自己的远端同步。
- **项目仓库 Git**：实际项目内容由项目仓库独立管理，不进入工作区 Git。
