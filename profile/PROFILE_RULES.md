# 用户画像内容规则

## 核心作用

定义 `profile/` 用户内容在写入和维护时共同遵守的提炼、组织与表达规范，使不同会话或 Agent 产生的内容保持准确、清晰、一致且便于维护。

## 通用内容规则

- **值得保留**：只记录值得长期保留，并且对以后理解用户或开展协作有帮助的内容。
- **忠实准确**：内容应准确反映用户表达或确认的信息；不确定的地方不要替用户猜测，也不要扩大原意。
- **尊重变化**：尊重用户当前的真实认识，不根据一次表现或简单标签固定定义用户；用户以后有新的认识时，可以更新原有内容。
- **独立理解**：内容应保留必要背景，使用户或新的 Agent 不查看原始对话也能正确理解。
- **清晰易读**：使用直白、自然、容易理解的语言，避免不必要的术语、复杂句子和含糊表达，方便用户阅读与审核。

## 各文件内容规则

### `PROFILE.md`

- **保持当前有效**：呈现用户当前有效的画像；认识发生变化时更新原有内容，不在这里堆积历史版本。
- **兼顾用户与 Agent**：保留对用户理解自己或 Agent 开展跨项目协作有长期参考价值的信息，在内容完整和默认读取量之间保持平衡。
- **沉淀画像结论**：具体事件、详细经历和完整思考过程不在这里展开；保留由这些内容形成的当前结论，以及理解结论所需的必要说明。

### `COLLABORATION.md`

- **保持当前有效**：只保留当前生效的长期协作偏好；偏好发生变化时更新原有内容，不在这里保留历史版本。
- **只写用户特定内容**：只记录相对于工作台默认规则的个性化补充或调整，不重复通用规则，也不记录仅适用于单次任务或具体项目的要求。
- **便于 Agent 执行**：尽量写清适用情况以及希望 Agent 采取的做法，避免只记录“更主动”“更高质量”等无法直接执行的模糊偏好。
- **控制默认读取量**：使用简短、直接的规则表述；具体事件、形成原因和完整思考过程不在这里展开，只保留理解和执行规则所需的说明。

### `insights/`

- **保留必要深度**：根据内容需要保留形成经验或认知所需的背景、关键思考、核心结论和适用条件，使以后能够理解它是如何形成和使用的。
- **结论优先**：先说明最重要的经验或认知，再展开必要的背景和思考过程，方便用户快速判断是否值得继续阅读。
- **详尽但不冗余**：不直接复制完整对话或无关事件经过；删除重复说明和不影响结论的细节，但不为追求简短而省略关键依据。
- **保持结构清晰**：根据内容使用小标题、短段落或列表，避免连续堆积大段文字；不强制所有洞察采用同一种固定模板。
- **说明适用边界**：结论只在特定场景下成立时，写清适用情况、限制和可能带来的行动启发，避免把局部经验当成普遍规律。

## 关联内容维护

- **权威快照优先**：`PROFILE.md` 和 `COLLABORATION.md` 分别代表当前有效的用户画像和协作规则；`insights/` 中的详细记录不能直接替代或覆盖两个快照。
- **按用途分层**：同一信息需要出现在不同文件时，按照各文件用途分别提炼；权威快照保留当前结论，`insights/` 保留必要细节，不在多个文件中原样重复。
- **日常不做全面检查**：平时新增或更新内容时，只按目标文件规则完成本次落盘，不自动扫描整个 `insights/` 或全面检查三个目标之间的一致性。
- **定期集中维护**：由用户根据实际需要发起维护，集中检查 `insights/` 与两个权威快照是否一致，并判断已有洞察能否补充、修正或优化 `PROFILE.md` 和 `COLLABORATION.md`；具体更新仍需用户确认。
